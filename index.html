How the estimate is calculated+

The selected 200 Astra episodes contain 14,196 observable HTTP requests. Their measured request time totals 70.43 hours, including failed and cancelled requests. Dividing every request duration by 8 gives 8.80 hours, or 2.64 minutes per episode. Task-group means use each group's own episodes.

The request and action sequence stays fixed for this calculation. VLA, robot execution, initialization and teardown are excluded. Request time includes network and service waiting; it is not isolated model thinking time. The actual service tier is unverified, and these figures are not an Ultrafast benchmark. HEXA's 9.05-minute mean is for RoboCasa365 with task skills and GPT-6 Astra at xhigh, under a different evaluation protocol.

Other policies

One harness. Every policy.

An execution layer for physical intelligence.

A robot policy brings the ability to act.
RoboHarness-Zero brings a way to guide it.

The policy does the moving. A language model holds the plan, watches for stalled progress, and steps in only then: first with a clearer instruction, and only if that fails with a short, bounded takeover. The policy's weights never change, and a new policy needs only a thin adapter and one profiling run.

How it works

Clear responsibilities.

Check the outcome. Keep the policy weights fixed.

Plan with context.

Task instructions, observations, and the policy's profile inform high-level decisions.

02

Execute with structure.

Operation identity, recovery permissions, and action budgets remain explicit.

03

Verify the outcome.

Local progress checks support execution. Environment evidence determines task success.

A new policy

Profile it.
Then run.

01

Profile.

Run the new policy by itself on 65 single-skill tasks, 15 times each: 975 short episodes. No language model, no training.

02

Calibrate.

Those runs become one small profile: how long each skill usually takes, and how long to wait before calling a stall.

03

Run.

Same harness, same prompts, same rules. Only the profile and a thin input-output adapter are new.

Questions,
answered.

Is profiling versus retraining a fair comparison?

They answer the same question in different ways: how do you get more out of a policy you already have? Retraining changes the weights and can teach new motions. RoboHarness-Zero leaves the weights alone and corrects decisions while the policy runs. What it needs first is one profiling run: 975 policy-only episodes, with no gradient steps and no language-model calls.

Does it really work with any policy?

Nothing in the harness is written for one policy. A new policy needs a thin input-output adapter and one profiling run; the rules, prompts, and tools stay the same. The results on this page use Xiaomi-Robotics-1, and more policies are being evaluated. One limit is by design: the harness fixes decisions, not motions, so it helps a policy that can already perform single skills reliably.

What does the language model actually do?

Mostly it watches. It holds the plan, checks whether the current step of the task is making progress, and steps in when it stalls: first with a clearer instruction, then, only if needed, with a short stretch of direct control before handing back. In the separate 250-episode GPT-6 Sol attribution study, 88% of the episodes that succeed both with and without the harness need no intervention, and 2% of all control steps come from its own tools.

Where does the gain come from?

Across the 200 matched scenes, 37 policy failures become successes and 11 policy successes become failures. The grouped bars compare success rates within single-skill, seen multi-step, and unseen multi-step tasks on that same subset.

What does it not fix yet?

Recovery. In the separate 250-episode Sol attribution study, among the 76 episodes that fail both with and without the harness, it raised a stall alarm in 63, so noticing the problem is not the bottleneck. Getting the arm out of it is: a recovery could be confirmed in only 2.

How is it evaluated?

The headline uses 200 selected held-out scenes from 50 tasks and 4 scene batches. Accepted Astra native outcomes are matched by scene to the completed policy-only reference. 10 selected results use a 600-second planning timeout. The environment decides success. The separate Sol attribution figures use 250 episodes.

What can the language model see and use?

The task instruction, camera images with depth, and feedback from execution. It can reword the instruction, call a small set of bounded motor tools, and read text files. It is given no task-specific hints.

Does it run on a real robot?

Not yet. Everything on this page is in simulation. In the separate 250-episode GPT-6 Sol study, the language model is called about 80 times per episode, mostly to look.
